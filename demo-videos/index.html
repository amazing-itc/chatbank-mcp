    Guia rápido

    Onboarding após o clone. Pré-requisitos: Java 21, Maven 3.9+, Node.js (Inspector).

    Endpoint MCP: http://localhost:8080/mcp (Streamable HTTP).

    mvn clean install
mvn spring-boot:run -pl starter-app
    npx @modelcontextprotocol/inspector@latest

    No Inspector: transporte Streamable HTTP → URL http://localhost:8080/mcp → Connect → aba Tools.

    Você deve ver o servidor chatbank-mcp 0.1.0 e as tools consultar_saldo, consultar_extrato, render_saldo e render_extrato.

    Widgets e OAuth (opcional)

    Depois de consultar_saldo / consultar_extrato, o modelo pode chamar render_saldo e render_extrato (HTML em kit-usecases/src/main/resources/ui).

    OAuth 2.1 de desenvolvimento: chatbank.kit.auth.enabled=true e usuários ana…delta / senha demo. O default continua sem login.

    Plugar o banco

    Contrato: kit-provider-api → BankingProvider (saldo e extrato).

    1. Copie adapter-sample/MeuBancoProvider.java.
    2. Implemente as chamadas ao core / BFF (mapa HTTP → tipos no guia ao lado).
    3. Registre o bean:
    @Bean
BankingProvider meuBanco(MeuClient client) {
    return new MeuBancoProvider(client);
}

    O mock é @ConditionalOnMissingBean e deixa de ser criado.

    Conecte seu banco

    O único ponto de troca é BankingProvider.

    Contrato: kit-provider-api/src/main/java/br/com/chatbank/kit/provider/BankingProvider.java

    public interface BankingProvider {
    Saldo consultarSaldo(ContaRef conta);
    Pagina<Lancamento> consultarExtrato(ContaRef conta, FiltroExtrato filtro);
}

    kit-provider-api não depende de Spring. Você implementa em Java puro e testa com JUnit.

    Como o mock entra (e como ele sai)

    Arquivo: mock-bank/.../MockBankConfiguration.java

    @Bean
@ConditionalOnMissingBean(BankingProvider.class)
BankingProvider mockBankProvider() {
    return new MockBankProvider();
}

    Se ninguém declara um BankingProvider, o mock é o banco. Se você declara um @Bean, o mock não é criado.

    Isso está testado em starter-app/src/test/java/.../ProviderSubstitutionIT.java.

    O que fazer

    1. Copie o esqueleto em adapter-sample/MeuBancoProvider.java.
    2. Implemente saldo e extrato contra o sandbox (veja o mapa abaixo).
    3. No starter-app (ou num módulo seu), registre:
    @Bean
BankingProvider meuBancoProvider(MeuClient client) {
    return new MeuBancoProvider(client);
}

    4. Suba de novo o starter-app e no Inspector use um contaId real do seu sandbox.

    Mapa HTTP → tipos do kit

    O adapter traduz a API do banco. A camada MCP não muda.

    Resposta do sandboxTipo do kit
    id da contacontaId em Saldo / argumento ContaRef
    nome do titularSaldo.titular
    saldo em reais (ex.: 1523.45)Money.brl(152345) — centavos, long
    item de extratoLancamento(id, data, tipo, descricao, Money.brl(…))
    lista + total + páginanew Pagina<>(itens, filtro.pagina(), filtro.tamanho(), total)

    FiltroExtrato já chega normalizado: pagina ≥ 1, tamanho entre 1 e 50, datas em LocalDate, tipo em TipoLancamento ou null.

    Exemplo mínimo de saldo:

    return new Saldo(conta.id(), body.titular(), Money.brl(body.centavos()));

    Exemplo mínimo de um lançamento:

    new Lancamento(
        item.id(),
        LocalDate.parse(item.data()),
        TipoLancamento.valueOf(item.tipo()),
        item.descricao(),
        Money.brl(item.centavos()));

    Se a API pagina por cursor e não por página 1-based: converta no adapter (pagina/tamanho → offset ou cursor interno). O contrato do kit continua Pagina.

    Erros (o modelo só vê a mensagem)

    HTTP / situaçãoO que lançarO que o Inspector mostra
    404 / conta desconhecidaContaNaoEncontradaException(conta.id())isError: Conta não encontrada: …
    403 / 429 / timeout / 5xxProviderException("mensagem segura")isError com essa mensagem
    Conta existe e não tem lançamentonew Pagina<>(List.of(), pagina, tamanho, 0)Extrato vazio, não é erro

    A mensagem de ProviderException vai para o modelo. Sem token, stack, trace id ou body interno.

    Conta inexistente é o mesmo comportamento nos dois métodos — o mock e o esqueleto fazem isso.

    Regras do contrato (não quebre)

    • contaId é identificador estável (o modelo reutiliza em follow-ups)
    • dinheiro em centavos + moeda (BRL)
    • não aceite senha, OTP ou PAN como argumento de tool

    Checklist

    • mvn test do seu adapter passa com uma conta de sandbox
    • Inspector com o bean real: saldo e extrato filtrado
    • Conta inválida em saldo e em extrato → Conta não encontrada
    • Conta válida sem lançamentos → página vazia, sem isError

    Como configurar no ChatGPT

    Mesmo caminho que um app publicado (como a WebMotors): o usuário adiciona o aplicativo no ChatGPT e depois conversa com ele. A diferença deste kit é que, enquanto não estiver no diretório, o time cria o conector à mão no modo desenvolvedor.

    O que o ChatGPT precisa

    • Conta ChatGPT paga (Plus, Pro, Business, Enterprise ou Edu) — conector custom exige isso
    • Servidor MCP em HTTPS público (não aceita localhost)
    • Endpoint Streamable HTTP: https://SEU-DOMINIO/mcp

    Em desenvolvimento, exponha a 8080 com um túnel (ngrok, Cloudflare Tunnel) e use a URL HTTPS que ele devolver + /mcp.

    1. Ligar o modo desenvolvedor

    1. 1Abra o ChatGPT no navegador (não no app mobile).
    2. 2Perfil → Configurações → Apps & Connectors (em algumas contas aparece como Aplicativos).
    3. 3Role até Advanced settings e ligue Developer mode.

    2. Criar o conector do kit

    1. 1Em Apps & Connectors, clique em Create (criar conector).
    2. 2 Preencha:
      Nome: ChatBank MCP
      Descrição: Saldo e extrato — somente leitura
      URL: https://SEU-HOST/mcp
      Autenticação: None no demo (OAuth só se chatbank.kit.auth.enabled=true)
    3. 3Marque que confia no aplicativo e clique em Create.
    4. 4Se pedir autorização, aceite. As tools devem aparecer: consultar_saldo, consultar_extrato, render_saldo, render_extrato.

    3. Usar na conversa (estilo WebMotors)

    Na WebMotors o usuário busca o app, conecta e começa um chat com @Webmotors. Aqui é o mesmo gesto, com o conector que você criou:

    1. 1Abra uma nova conversa.
    2. 2No + do compositor, escolha Developer mode e selecione ChatBank MCP como fonte.
    3. 3Pergunte em linguagem natural. O modelo chama as tools — você não cola JSON.

    Exemplos para colar:

    Qual o saldo da conta-pf-ana?

Mostra o extrato de PIX da conta-pf-carla em agosto de 2026.

A Ana consegue pagar um almoço de 40 reais?

Manda um PIX de 25 reais para o João.

    Os três primeiros devem chamar consultar_saldo / consultar_extrato. O último não deve chamar tool de envio — o kit é somente leitura.

    Quando o plugin estiver no diretório

    Aí o caminho fica idêntico ao da WebMotors, sem modo desenvolvedor:

    1. 1Menu lateral do ChatGPT → Aplicativos / Plugins.
    2. 2Busque o nome publicado pelo banco e clique em Conectar.
    3. 3Nova conversa → @NomeDoBanco → “qual o saldo?” / “extrato de agosto”.

    Quem publica é a instituição (domínio próprio, verificação OpenAI, privacy policy). Este repositório não é um listing.

    Se não listar as tools

    • Developer mode está mesmo ligado? Sem ele o ChatGPT trata o servidor como fonte de pesquisa e some as tools de leitura.
    • A URL termina em /mcp e é HTTPS alcançável da internet?
    • Feche o chat e abra outro depois de criar o conector.
    • No Inspector, o mesmo endpoint precisa responder tools/list com as quatro tools.
